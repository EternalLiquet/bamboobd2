# Small issue and review workflow

1. Open one issue for a falsifiable question or bounded deliverable. State evidence, competing hypothesis, affected files, safety boundary, acceptance checks and stop condition. Use the [issue template](templates/issue.md).
2. Before a future edit, inspect the repo, prepare a file-by-file proposed diff, and wait for explicit owner “go” per `AGENTS.md`. The 2026-10-29 owner handoff for [#27](https://github.com/EternalLiquet/bamboobd2/issues/27) is a limited exception for its linked software issues through that delivery: routine code, documentation, tests, commits, pushes, draft PRs, review fixes and clean merges after checks and the two independent review stages may proceed. The sequence is GPT-6 Astra medium orchestration, GPT-6 Sol high implementation, GPT-6.1 Sol extra-high independent review, then GPT-6 Astra high independent final review and merge. All hardware, privacy, permissions, dependencies, security and branch-rule gates still apply. The ordinary file-by-file rule resumes after delivery.
The later 2026-10-29 [#41 continuation](https://github.com/EternalLiquet/bamboobd2/issues/41) separately authorizes only [#42 saved-session finder](https://github.com/EternalLiquet/bamboobd2/issues/42) and narrow supporting fixes through delivery or 13:00 UTC, whichever occurs first. The ordinary gate resumes thereafter. The same offline safety limits, hosted checks and independent Sol extra-high then Astra high review stages apply.

3. Work on a branch. Keep protocol observations in [evidence logs](templates/evidence-log.md), consequential choices in [ADRs](templates/adr.md), and external-source comparisons in [research notes](templates/research-note.md). Cite exact versions and licenses; distinguish a maintainer claim from an independent test.
4. For code later, introduce a sanitized capture/replay fixture before a live dependency. Version golden input and expected output separately. Hash source input, explain intended decoder deltas, and retain a minimized failing fixture. Property tests should cover stream chunking, irrelevant frames and valid round trips where an encoder exists. Fuzz only offline parsers with limits. Use a fake transport for timeout, negative response, reconnect and ordering behavior.
5. An independent reviewer checks safety scope, provenance/license, tests, negative cases and the exact commit hash. Re-run checks against that commit after changes; earlier results do not transfer. The reviewer cannot promote an inference to a verified vehicle fact.
6. Before completion, inspect the full diff and check status, disclose commands run and failures, obtain actual advisor review where available, and list remaining vehicle validation. Do not claim integration or hardware verification from documentation alone.

The current code's commands and their scope are in [BUILD.md](BUILD.md). For the overnight debug APK, run `./gradlew -p core check` and `./gradlew :app:testDebugUnitTest :app:lintDebug :app:verifyNoForbiddenPermissions :app:assembleDebug`. The latter checks both merged-manifest variants while testing and linting the debug variant. The broader `:app:check` remains available. Record the exact source SHA and outputs; these host checks do not establish vehicle behavior.
