> Use executing-plans for this small native continuation; independent review before delivery.

**Goal:** Collect complete F187 part-number data on the two already-observed routes.
**Architecture:** Reuse v4 startup, raw framing and ownership. Keep CFC0; after exactly a 14-byte positive first frame and terminal prompt, send one manual `30020A0000000000` (CTS, block size2, separation10ms) to the same header. Collect CF21 and CF22, trim padding to announced length, require prompt. No automatic FC, no retries.
**Stack:** Existing Kotlin core/Android Compose; no dependencies or permissions.
**Spec/design:** This document records the continuation authorized by the owner after v4 results. Manual FC was chosen over adapter auto-FC because it gives a strict host frame count and validates the first frame before sending. Auto-FC can respond to each FF before host validation. Manual timing may miss the unknown ECU flow-control deadline; no recovery is attempted.

## Bounds and review focus

- Two F187 requests plus at most one FC per endpoint, four attempted host CAN writes total. Keep setup and routes unchanged.
- Accept FF length14 only; validate service/DID/responder before FC. Reject wrong/duplicate/out-of-order CF, extra payload frame or truncated transfer. CF padding is excluded from identity.
- Require terminal prompt before FC; retain existing 2s exchanges, 5s pending window and60s total. FC collection max2s. No FC after cancellation or incomplete initial exchange.
- Preserve raw provenance, partial evidence and private report/export. Complete part number is reported data, not verified ECU attribution. No maintenance reads or resets.
- Tests use constructed identities, never publish owner's raw captures. Existing single-frame/negative/startup tests remain.
