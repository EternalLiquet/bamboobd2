# Cayenne maintenance read: evidence before implementation

Reviewed 2026-10-30 for [#58](https://github.com/EternalLiquet/bamboobd2/issues/58), with [#59](https://github.com/EternalLiquet/bamboobd2/issues/59) and [#60](https://github.com/EternalLiquet/bamboobd2/issues/60) as the bounded deliverables. The owner target is a 2014 Cayenne S (958, V8), Veepeak OBDCheck BLE (not BLE+), Bluetooth Classic and Samsung S24. No exact, applicable maintenance read definition was found. The app therefore has no supported oil or inspection interval decoder for this target. No vehicle or adapter action was part of this review.

## Evidence required for an interval decoder

“Documented” below means a source claim about a tool or framing rule. Generic owner observations are limited to the closed [#7](https://github.com/EternalLiquet/bamboobd2/issues/7), [#14](https://github.com/EternalLiquet/bamboobd2/issues/14) and [#15](https://github.com/EternalLiquet/bamboobd2/issues/15) sessions. They do not identify the cluster. Each unknown remains a block, even if a displayed value looks plausible.

## Offline transport evidence

The two `SYNTHETIC` Mode 03 fixtures use existing allowlisted requests and constructed generic DTC bytes. `rule-03-can-interleaved-multiframe` gives 7E8 and 7E9 distinct multi-frame replies, with completion order preserved and each code attached to its responder. `rule-03-can-interleaved-incomplete` lets 7E9 finish while 7E8 lacks its final consecutive frame before the prompt; the conservative parser reports `malformed` for the exchange. The IDs illustrate the ELM327DSL p44 framing example and are not Porsche module addresses. There is no interval decoding.

The existing `GoldenFixtureTest`, `FragmentationTest` and `ReadPlanAndHygieneTest` load these files automatically through `ProtocolFixtures` and `FakeTransport`, including every byte split, seeded chunks, allowlist and provenance checks. Earlier fixtures cover single-responder multi-frame and two-responder single-frame replies. `FragmentationTest.streamEndingBeforeThePromptIsIncomplete` covers a missing prompt; `MalformedAndStatusTest` covers frame order, `NO DATA` and adapter errors; `ElmObdReaderTest` covers pending replies, deadlines, disconnect, retry limits and cancellation; `RequestPolicyTest` covers denied requests. `AdapterBenchCheckTest` already exercises ATI, AT@1 and ATRV offline and is unchanged. These checks establish parser behavior on constructed bytes. They do not establish the Porsche route, owned adapter flow control, field definitions, units or an on-car read.

## Minimum owner evidence proposal

1. **Existing evidence only.** The owner may transcribe the instrument-cluster part, hardware and software identifiers and market from an already lawful report, excluding VIN. Also transcribe the exact service-counter labels and displayed values with units from an existing observation. No whole export, new connection or raw private capture is requested. Labels and displayed values cannot prove wire semantics; an identity label alone cannot prove a definition applies.
2. **Separate stage, presently blocked.** Once an applicable source defines the module route and finite read-only list, prepare an owner-operated plan naming the car/module, tool and adapter, one setup and one read per documented field, expected reply shapes, timing limits derived from that procedure and abort criteria. The owner must approve that plan separately. A required session change outside read-only scope or security access leaves this stage blocked. A tool mode that automatically collects VIN, changes state or scans unrelated modules is unsuitable unless a separately reviewed mode avoids it.

The future plan must require an authorized operator, stationary vehicle and stable power under [the live-test gate](LIVE_TEST_GATE.md). Stop on unexpected behavior, wrong module or response, missing prerequisite, timeout, adapter reset/error or cancellation. No scan, fallback address, retry loop, automatic reconnect, reset, write, routine or security access belongs in this proposal. Keep original captures private and immutable; any later fixture requires separate provenance and sanitization review. No numerical live voltage or timing is inferred from generic advice.
